# Destiny Guide 이용 통계 사용 안내

통계 화면: https://angrieta.github.io/Destiny_Guide/analytics_page.html

이 통계는 사이트 콘텐츠를 개선하기 위한 익명 이용 횟수입니다. 게임 서버의
접속자 수나 게임 내 행동을 수집하는 기능은 아닙니다. 별도 분석 서비스를
열 필요 없이 사이트의 **이용 통계** 화면에서 확인합니다.

## 확인 순서

1. 헤더의 **이용 통계**를 누르거나 위 주소를 엽니다.
2. **7일 / 30일 / 90일** 중 하나를 선택합니다. 페이지와 아이템 표에 같은 기간이 적용됩니다.
3. 위쪽 콘텐츠 표에서 **페이지**를 선택하면 많이 방문한 공략을 확인할 수 있습니다.
   **세부 기능**에서는 등록된 공략 구간과 도구의 노출·사용을 비교합니다.
4. **아이템 카드 이용 통계**로 내려가면 아이템별 팝업과 획득 경로 사용량이 보입니다.
   이름으로 검색하거나 집계 항목을 바꿔 내림차순 정렬합니다.
5. 아이템 이름을 누르면 그 아이템 팝업이 열립니다.
6. **CSV 다운로드**는 현재 페이지/세부 기능 표를, **아이템 통계 CSV 다운로드**는
   현재 검색·정렬된 아이템 표를 저장합니다. 엑셀에서 열 수 있습니다.
7. 최신 숫자를 다시 받으려면 화면을 새로고침하거나 기간을 다시 선택합니다.
   통계 화면은 자동 새로고침을 하지 않습니다.

## 페이지 표의 의미

| 항목 | 집계 기준 | 해석할 때 주의할 점 |
| --- | --- | --- |
| 조회 | 해당 페이지를 열었을 때 | 고유 방문자 수가 아닙니다. |
| 15초 열람 | 탭이 보이는 상태의 시간이 누적 약 15초 이상 | 완독이나 정확한 체류 시간은 아닙니다. |
| 사용 | 본문의 링크·버튼·검색·필터 등 조작 | 실제 검색어나 입력 내용은 전송하지 않습니다. |
| 조회 발생일 | 선택 기간 중 조회가 있었던 날짜 수 | 조회 수와 별개의 지표입니다. |
| 마지막 조회 | 마지막으로 조회된 날짜 | UTC 기준이며 접속 시간은 표시하지 않습니다. |
| 이전 기간 대비 | 같은 길이의 직전 기간과 조회 수 차이 | 두 기간 전체에 수집 기록이 있어야 표시합니다. |

예를 들어 7일 조회가 30이고 이전 7일 조회가 20이면 이전 기간 대비는 +10입니다.
수집을 시작한 지 얼마 되지 않았으면 비교값은 **—**로 표시됩니다.
세부 기능 조회는 등록된 영역이 화면에 2초 이상 걸쳐 보일 때 집계합니다.
세부 기능은 모든 문단이 아니라 사이트에 지정된 공략 구간·도구만 대상입니다.

## 아이템 표의 의미

아이템 표는 **아이템 도감(item_page.html)**의 팝업에서 발생한 행동을 셉니다.
데이터베이스 페이지의 별도 아이템 창이나 다른 페이지의 장비 링크까지 합산하지 않습니다.

| 항목 | 언제 올라가는가 |
| --- | --- |
| 팝업 열기 | 카드 클릭, Enter/Space, 아이템 직접 링크로 상세창을 열었을 때 |
| 드랍표 클릭 | 팝업 안에서 드랍표로 이동하는 링크를 눌렀을 때 |
| 조합·계획표 클릭 | 팝업 안에서 조합 페이지나 재료 계획표로 이동하는 링크를 눌렀을 때 |
| 재료 경로 펼치기 | 조합의 재료 획득 경로 또는 그 안의 개별 재료를 펼쳤을 때 |
| 출처 클릭 | 획득 방법 안의 이벤트 공략·교환 안내·공식 출처 링크 등을 눌렀을 때 |

각 숫자는 **아이템별·행동별·브라우저 탭 세션별 최대 1회**입니다.
예를 들어 한 탭에서 Dark Flow를 5번 열고 드랍표 링크를 3번 눌러도
Dark Flow의 팝업 열기 1, 드랍표 클릭 1입니다. 다른 아이템은 각각 따로 셉니다.
재료를 여러 개 펼쳐도 그 결과물 아이템의 재료 경로 펼치기는 1입니다.
Dark Flow 팝업에서 Parasitic Gene의 드랍표를 누른 행동은 Dark Flow 행에 기록됩니다.

새로고침, 뒤로 가기, 언어 변경으로 같은 행동의 숫자가 계속 늘지 않게 했습니다.
다만 탭·브라우저·기기가 달라지면 별도 집계될 수 있고, 탭 복제·세션 복구 방식은
브라우저마다 다릅니다. 그래서 사람 수나 정확한 클릭 총수로 해석하면 안 됩니다.
각 열은 같은 이용자의 서로 다른 행동일 수 있으므로 합산해 이용자 수로 쓰지 않습니다.

## 콘텐츠 개선에 사용하는 예

- **팝업 열기와 드랍표 클릭이 모두 높은 아이템**: 획득 경로의 최신성·퀘스트 조건을 우선 점검합니다.
- **재료 경로 펼치기가 많은 아이템**: 필요한 수량과 하위 조합 안내를 우선 보강합니다.
- **조회는 많고 15초 열람·사용은 적은 페이지**: 방문 목적을 빨리 해결한 것일 수도 있고,
  원하는 내용을 못 찾은 것일 수도 있습니다. 숫자만으로 판단하지 말고 본문·동선을 확인합니다.
- **조회가 적은 공략**: 30일 또는 90일을 보고 시즌성·고난도 전용 여부·접근 경로를 함께 판단합니다.
  0회라는 이유로 바로 삭제하지 않습니다.

## 언제부터 보이나요?

배포 후 실제 방문부터 쌓입니다. 과거에 수집하지 않은 클릭을 복구할 수는 없습니다.
첫 관측 전의 아이템 지표는 **—**, 수집이 시작된 뒤 기록이 없는 항목은 **0**입니다.
통계 API 장애는 0으로 표시하지 않고 오류 안내를 보여줍니다.
날짜와 기간 경계는 UTC이며 한국 시간 오전 9시에 날짜가 바뀝니다. 오늘 수치는 집계 중입니다.
사이트 자체 확인을 위해 운영자가 여는 공개 페이지와 카드도 일반 이용과 동일하게 집계됩니다.
통계 화면 자체와 localhost 개발 화면은 수집에서 제외합니다.

## 저장되는 정보와 한계

Cloudflare D1의 집계 표에는 날짜, 이벤트 종류, 페이지 경로, 고정 아이템 키/기능 키,
누적 횟수만 저장합니다. 이 통계 표에는 IP, 쿠키, 방문자 식별자, User-Agent,
검색어, 폼 입력값을 저장하지 않습니다. 사이트 명부·건의사항의 별도 데이터와는 구분됩니다.
브라우저의 sessionStorage에는 같은 행동의 중복 집계를 막는 표시만 저장합니다.
네트워크 사업자는 통상적인 요청 메타데이터를 처리할 수 있습니다.

보고서는 공개 주소에서 누구나 볼 수 있는 합계입니다. 개인별 방문 기록·히트맵·
마우스 궤적·화면 녹화 기능은 없습니다. 광고 차단기, 스크립트 비활성화,
네트워크 오류로 누락될 수 있고 공개 수집 API를 통한 허위 요청도 완전히 막지는 못합니다.

## 운영 메모

- 사이트는 GitHub Pages, 수집 API와 집계 데이터는 기존 Cloudflare Worker/D1에서 운영합니다.
- 사이트와 API는 별도로 배포해야 합니다. 데이터베이스는 기존 명부와 건의사항 표를 유지하고
  `api/migrations/0002-analytics.sql`의 `CREATE TABLE IF NOT EXISTS`만 추가합니다.
- 아이템 허용 목록은 빌드 시 `data/analytics-items.json`으로 생성됩니다.
  신규 아이템 추가 시 사이트와 Worker 모두 새 목록으로 배포해야 합니다.
- 같은 DB를 계속 쓰면 배포해도 집계는 유지됩니다. 초기화용 `schema.sql`을 다시 실행하지 마세요.
