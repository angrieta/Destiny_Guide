# 닉네임 명부 API — 설치 안내

사이트는 GitHub Pages 정적 배포라 서버가 없다. 방문자가 남긴 글이 남아 있으려면
쓰기 가능한 곳이 따로 필요해서, 이 Worker 와 D1 을 **사이트와 별개로** 띄운다.
사이트 빌드·배포 워크플로에는 아무 영향이 없다.

로그인은 없다. 글을 남길 때 정한 비밀번호를 아는 사람만 그 글을 고치고 지운다.
**디스코드 앱 등록 같은 것은 필요 없다.** 아래 다섯 줄이 전부다.

---

## Windows PowerShell 주의

`npx` 를 그대로 치면 이렇게 막힐 수 있다.

```
npx : 이 시스템에서 스크립트를 실행할 수 없으므로 ... npx.ps1 파일을 로드할 수 없습니다.
```

PowerShell 이 `.ps1` 실행을 막고 있는 것이다. **보안 설정을 바꾸지 말고**, 뒤에 `.cmd`
를 붙여 `npx.cmd` 로 부르면 그냥 넘어간다. 아래 명령들은 전부 그렇게 적어 뒀다.

---

## 순서

터미널을 열고 이 폴더로 간다.

```bash
cd "C:\Users\webma\Downloads\Destiny_Guide-landing (3)\Destiny_Guide-landing\api"
```

**1. Cloudflare 로그인** — 브라우저가 열리면 승인한다. 계정이 없으면 무료로 만든다.

```bash
npx.cmd wrangler login
```

**2. 데이터베이스 만들기**

```bash
npx.cmd wrangler d1 create destiny-roster
```

출력에 나오는 `database_id = "..."` 를 `wrangler.toml` 의 같은 줄에 붙여 넣는다.

**3. 표 만들기**

```bash
npx.cmd wrangler d1 execute destiny-roster --remote --file=./schema.sql
```

**4. 운영자 비밀번호 넣기** — 스팸이나 사칭 글을 지울 때 쓴다. 아무 글이나 지울 수
있으니 길게 잡는다. 이 값은 Cloudflare 에만 저장되고 저장소에는 남지 않는다.

```bash
npx.cmd wrangler secret put ADMIN_PASSWORD
```

물어보면 입력하고 엔터. 화면에 안 보이는 게 정상이다.

**5. 배포**

```bash
npx.cmd wrangler deploy
```

끝나면 `https://destiny-roster.<서브도메인>.workers.dev` 주소가 나온다.
그 주소를 `scripts/roster.js` 맨 위 `API_BASE` 에 넣으면 페이지가 붙는다.

---

## 비밀번호를 어떻게 다루는가

- **그대로 저장하지 않는다.** PBKDF2(SHA-256, 10만 회)로 늘린 해시와, 줄마다 다른
  소금만 남긴다. 표가 통째로 새어 나가도 원래 값을 되돌릴 수 없다.
- 비교는 **일정한 시간**이 걸리게 한다. 보통의 문자열 비교는 틀린 지점에서 바로
  끝나서, 응답 시간 차이로 앞에서부터 한 글자씩 맞춰 볼 여지를 준다.
- 비밀번호는 **응답에 절대 실리지 않는다.** 해시와 소금도 마찬가지다.
- 그래도 페이지에서는 "쓰던 비밀번호 말고 아무거나" 라고 안내한다. 사람들은 실제로
  재사용하고, 이건 그 정도로 지킬 가치가 있는 곳이 아니다.

## 이 방식으로 되는 것과 안 되는 것

| | |
|---|---|
| 되는 것 | 내가 남긴 글을 **남이 고치거나 지우지 못한다** |
| 안 되는 것 | **남의 디스코드 닉으로 등록하는 것**은 막지 못한다 |

로그인이 없으니 "이 디스코드 계정이 정말 본인인가" 는 확인할 방법이 없다. 사칭 글이
올라오면 운영자 비밀번호로 지우면 된다. 이 점은 페이지에도 적어 두었다.

## 비용

Cloudflare 무료 한도는 Worker 하루 10만 요청, D1 하루 500만 행 읽기다.
이 규모의 커뮤니티 명부로는 근처에도 가지 않는다.

## 익명 이용 통계 켜기

기존 D1 데이터베이스를 쓰고 있다면 `schema.sql` 을 다시 실행하지 말고, 아래의 추가
마이그레이션만 한 번 실행한다. 기존 명부와 건의사항 데이터는 그대로 남는다.

```bash
npx.cmd wrangler d1 execute destiny-roster --remote --file=./migrations/0002-analytics.sql
npx.cmd wrangler deploy
```

정적 사이트도 새 빌드로 배포하면 모든 페이지가 조회를 전송하고, 헤더의 **이용 통계**
페이지에서 최근 7일·30일·90일 기준 전체 콘텐츠의 조회·사용을 볼 수 있다.

- 페이지 조회는 같은 브라우저 탭 세션에서 페이지별 한 번만 센다.
- 화면을 앞에 둔 시간이 15초 이상이면 `engaged_view`, 세부 콘텐츠가 화면에
  2초 이상 걸쳐 보이면 `content_view`로 센다. 완독이나 고유 방문자를 뜻하지 않는다.
- 본문 링크·버튼·검색·필터 조작은 `content_use`로 센다. 입력한 검색어나 폼 내용은
  보내지 않는다. 페이지 전체와 등록된 세부 기능별로 각각 탭 세션당 최대 1회다.
- 클래스·레벨 버튼은 직접 선택했을 때만 기록한다. 기본 HUmar/LV100을 자동으로
  기록하지 않으므로 기본값에 의한 편향을 줄인다.
- D1에는 날짜, 이벤트 종류, 페이지 경로, 선택값, 횟수만 저장한다.
- 집계 DB에는 IP 주소, 쿠키, User-Agent, 방문자 식별자를 저장하지 않는다.
  네트워크 제공자는 일반 요청 메타데이터를 처리할 수 있다.
- 로컬 개발 주소에서는 조회 이벤트를 보내지 않는다.
- 통계 화면 자체는 신규 수집에서 제외한다. 공개 API의 수치는 조작될 수 있는
  참고 집계이며, 검증된 방문자 수가 아니다.

### 콘텐츠 검토 화면 (v2)

- 빌드 시 실제 페이지 목록을 만들어 조회 0인 콘텐츠도 표시한다. 헤더·캐러셀
  조각은 페이지로 세지 않는다. 향후 독립 HTML 페이지도 자동으로 목록에 들어간다.
- 페이지 / 세부 기능 전환, 검색, 조회 적은 순, 사용 많은 순, 조회 0~5 필터,
  CSV 내려받기를 지원한다. 콘텐츠를 자동으로 삭제하는 기능은 없다.
- 이전 동일 길이 기간과의 차이, 조회 발생일 수, 마지막 조회일은 UTC 기준이다.
  최초 수집이 비교 기간보다 늦으면 비교값을 숨긴다. 오늘은 집계 중이다.
- `measurement: v2`의 첫 수집일 이전에는 세부 지표를 알 수 없으므로 ‘—’로 표시한다.
  네트워크 오류·구버전 API 응답을 조회 0으로 표시하지 않는다.
- v2는 같은 `analytics_daily` 표를 사용하므로 새 마이그레이션은 필요 없다.
  `0002-analytics.sql`을 아직 적용하지 않았다면 먼저 적용한다. `schema.sql`을
  재실행하면 기존 데이터가 사라질 수 있으므로 대체 수단으로 사용하지 않는다.
- API와 사이트는 각각 배포해야 한다. 현재 로컬 구현은 원격 배포를 자동 수행하지 않는다.

### 로컬 검증

프로젝트 루트에서 개발 서버를 3003 포트로 실행한 뒤 별도 터미널에서:

```powershell
pnpm.cmd run prepare:static
node tests/guide-revision.mjs
```

실제 Worker 코드를 메모리 SQLite로 검증하고, 12클래스 × 4레벨 × 5언어,
모바일 레이아웃, PB 단계, 통계 정렬·필터·CSV·오류 상태와 수집 중복 방지를 검사한다.
통계 예시값은 테스트에서만 주입하며 원격 API로 전송하지 않는다.

## 나중에 고칠 일이 생기면

```bash
npx.cmd wrangler deploy              # 코드나 vars 를 바꾼 뒤
npx.cmd wrangler secret put ADMIN_PASSWORD   # 운영자 비밀번호 교체
npx.cmd wrangler tail                # 실시간 로그
```

표를 비우고 처음부터 다시 하려면 `schema.sql` 을 그대로 다시 실행하면 된다
(맨 위에서 기존 표를 지우고 새로 만든다 — **기존 글이 전부 사라진다**).
